Clean the inbox.
Then keep it clean.

A four-part toolkit that clears a cluttered Gmail inbox and builds the rules that keep it clear — as a byproduct of the cleanup itself. It runs entirely on your own machine against your own Google project, works on metadata only, never reads the body of your email, and never permanently deletes anything.

The big idea

Why most inbox cleanups fail

Clearing the backlog is the easy part. The reason you're back at 5,000 unread a year later is that nobody sets up rules afterward — the cleanup burns the energy you'd need to build the system that prevents the next one.

This toolkit flips that. Every time you tell it "trash everything from this sender," it doesn't just clear the backlog — it also creates a Gmail filter that automatically handles future mail from that sender. One decision, applied backward and forward. The rules aren't a separate chore you'll never get to. They fall out of the work you're already doing.

What's in the box

The four-stage pipeline

Think of it as an assembly line. The first two stages only read — they cannot change anything. The last two can write, but default to a dry run and ask you to confirm before touching a single message.

Two ideas that make it safe

Before you touch anything

Idea 01

Metadata, not content

It works on the facts about each email — who, what subject, what date — never the body. A privacy win and a speed win: metadata is tiny, so tens of thousands of messages process fast.

Idea 02

Trash ≠ delete

Cleanup moves mail to Trash (recoverable 30 days) or Archive (kept forever, just out of the inbox). The permanent-delete operation is deliberately never used.

Getting started

From zero to a cleaner inbox

The path at a glance. The full guide in the repo spells out every click and command, including the one-time Google setup. This is the map.

  1. Set up a free Google Cloud project

    You create your own credential that authorizes this toolkit to access your mailbox. You can't use anyone else's, and no one can use yours — that's the design, and it's what keeps your inbox safe.

    ⚠

    Keep credentials.json private — treat it like a password. The included .gitignore blocks it from being committed by accident.

  2. Install Python and the toolkit

    Check you have Python, then install the two libraries the scripts need.

    # check Python (need 3.9+)
    python3 --version

    # install dependencies
    pip3 install -r requirements.txt

  3. Take a read-only snapshot

    Completely safe — it only reads. The first run opens your browser to sign in. When it finishes, open sender_report.html and study it. This report is the thinking part; the scripts are just muscle.

    python3 ingest.py

  4. Build your rules and dry-run

    Edit the RULES block with senders from your report, then run with no flag. A dry run changes nothing — it shows how many messages each rule would affect. Read those counts.

    # dry run — connects to nothing, changes nothing
    python3 cleanup_basic.py

  5. Go live

    When the counts look right, add --execute. It asks you to type yes before anything happens, then cleans up and creates your filters.

    python3 cleanup_basic.py --execute

  6. Tackle the hard cases — and let AI help

    Run analyze.py for the deeper report, then use cleanup_advanced.py for mixed senders. The guide includes a copy-paste prompt that hands your analysis to an AI assistant to draft the advanced rules — you review and approve every one.

    python3 analyze.py
    python3 cleanup_advanced.py # dry run first, then --execute
✓

The golden rule: always dry-run and read the counts before any --execute. If a rule you expected to hit thousands shows zero, your pattern is probably mistyped. Nothing replaces your own eyes on the dry-run output.
